§ 05

深入評估

Detailed Assessment

點擊任一卡片展開完整評估。內容含可做項目、技術選型、風險。

01
CRM ‧ 會員行銷自動化
+
Scope · 能做什麼
  • 會員 RFM 分群（消費頻率／金額／最近消費）
  • 自動行銷流程：生日券、流失喚回、首購禮、消費滿額升等
  • 多通路觸發：LINE OA push、簡訊、Email
  • 優惠券系統（單次／多次／堆疊規則、防濫用）
  • 點數系統升級（多店通用、有效期、轉贈）
Stack · 技術選型
  • 後台：Laravel + Filament 或 Livewire + Vue
  • 排程：Laravel Scheduler + Queue (Redis/Horizon)
  • LINE 整合：LINE Messaging API
  • 簡訊：三竹、Mitake、every8d
Risk · 主要風險
  • 跟既有 POS 資料庫整合方式（API or 直連 DB？）
  • 大量推播時序：10 萬會員 broadcast 要分批避免 LINE rate limit
02
進銷存深化
+
Scope · 能做什麼
  • BOM 表（一杯珍奶用幾克茶葉、幾顆珍珠）→ 自動扣庫存
  • 多倉管理（總倉 → 分店倉）
  • 自動進貨建議（安全庫存、再訂貨點）
  • 盤點 App（Flutter，掃條碼）
  • 損耗 / 報廢 / 內部消耗記錄
  • 供應商管理、採購單、應付帳款
Stack · 技術選型
  • Laravel + spatie/laravel-event-sourcing（庫存異動 audit trail）
  • Flutter + mobile_scanner（條碼掃描）
  • 拒絕用 ORM 直接更新庫存 → 用 DB transaction + 行鎖避免超賣
Risk · 主要風險
  • 餐飲業 BOM 很雜（半成品、加料、客製化），規格定義要花時間
  • 跟 POS 即時扣庫存的耦合度需討論
03
排班系統— Sweet Spot
+

這是 Laravel + Flutter 組合的甜蜜點 — 既有 Web 後台，又有員工手機 App。

Scope · 能做什麼
  • 員工 App：看班表、換班申請、請假、打卡（GPS / Wi-Fi / NFC）
  • 店長後台：拖拉式排班、人力成本預估、勞基法合規檢查
  • 整合薪資計算
  • 跨店人力調度
Stack · 技術選型
  • Flutter（員工 App）+ FCM 推播 + geolocator 打卡
  • Laravel + Filament Calendar 或 FullCalendar
Why Sweet Spot · 為何是甜蜜點

餐飲業排班是高頻痛點，但市面方案（LineUp、班表通）整合 POS 不深。 跟 POS 結合可以做人力效率分析 — 每小時人力成本對比營收， 這是肚肚連鎖客戶會買單的故事。

04
開放 API ‧ Open Platform
+
Scope · 能做什麼
  • 把 POS 的訂單、會員、商品開放給合作夥伴
  • Webhook 通知第三方（訂單成立、會員升等）
  • OAuth2 授權店家
  • 沙盒環境、API 文件站、SDK
Stack · 技術選型
  • Laravel Passport 或 Sanctum
  • API 文件：Scribe 或 Scramble
  • Rate limiting：Laravel built-in throttle
  • Webhook 重送：Queue + exponential backoff
Strategic Value · 戰略價值

肚肚有王品 + 鴻海背景，生態系是他們的競爭護城河。 做 Open Platform 等於幫他們把連鎖客戶鎖死 — 一旦串接，遷移成本超高。 這條線的長期合約價值最高。

05
第三方整合中介層
+
Payment · 金流
  • 綠界 ECPay、藍新 NewebPay、紅陽 ESafe
  • 玉山 / 中信 / 國泰收單（需簽 NDA）
  • LINE Pay Merchant、街口
  • Apple Pay / Google Pay
Invoice · 發票
  • 綠界、ezPay、藍新都有完整電子發票 API
  • B2B 三聯、B2C 二聯、捐贈、作廢、折讓、進銷項申報
ERP · 會計
  • 鼎新 Workflow ERP、正航、SAP、Oracle NetSuite
  • 透過 CSV 排程匯出 或 API 中介層
  • 做一個 iPaaS-like 中介層（Laravel）統一收進來再分發
06
BI ‧ 數據分析儀表板
+
Scope · 能做什麼
  • 即時營收儀表板（多店、多時段、品項熱度）
  • 預測：下週備料量、來客數預估
  • 異常告警：營收驟降、退單異常、員工異常打折
Stack · 技術選型
  • 後端：Laravel + ClickHouse 或 TimescaleDB
  • 圖表：Apache ECharts / Chart.js
  • 即時：Laravel Reverb 或 Pusher
  • 資料量超大（億級）建議：Metabase / Superset + Laravel 權限層
Risk · 主要風險
  • 資料量級不明，Laravel + MySQL 處理上億筆會痛
  • 跨店即時聚合建議分冷熱資料：熱 Redis、冷 OLAP
07
海外市場（多語 ‧ 多幣 ‧ 跨境）
+
Scope · 能做什麼
  • 多語系：Laravel localization + spatie/laravel-translatable
  • 多幣別：每筆交易記原幣 + 結算幣 + 匯率
  • 多稅制（VAT、GST、消費稅、服務費）
  • 跨境金流：Stripe、Adyen
Risk · 主要風險
  • 中國市場要走獨立部署（VPN / ICP / 微信支付 / 支付寶）
  • 東南亞每個國家發票稅制不同
08
硬體周邊（KDS · Kiosk · 排隊機）
+

Flutter 在這題是強項 — 一份程式碼可以跑 iPad、Android 平板、Windows、Linux。

KDS · 廚房顯示
  • Flutter 跑在 Android TV / 平板
  • WebSocket 即時收單（Laravel Reverb / Pusher / Soketi）
  • 顏色狀態、計時、完成回拋
Kiosk · 自助點餐機
  • Flutter for Windows / Android
  • 整合刷卡機（USB / RS232 / TCP）
  • 整合發票機（EPSON ESC/POS）
Risk · 主要風險
  • 硬體驅動是大坑：發票機 ESC/POS 指令、刷卡機 EDC 規格
  • 建議只做螢幕端，硬體外設由肚肚既有方案串
09
AI 應用 — LLM 類
+
Doable · 可以做
  • AI 客服：OpenAI / Claude / Gemini API + RAG（pgvector / Pinecone）
  • 銷售預測：Laravel 排程跑 Python 微服務（FastAPI）
  • 菜單推薦：協同過濾
  • 自動回覆評論（Google Maps）
Avoid · 不要主動接
  • 影像辨識（菜品偵測、桌況、人流計數）
  • 語音點餐（ASR + NLU）
Alternative · 替代策略
  • 影像：Google Vision / AWS Rekognition / Azure CV
  • 語音：Whisper API / Google Speech-to-Text
  • 你們負責串接 + 業務邏輯，模型外包給雲服務
10
店家後台 UI 重構
+
Verify First · 先問清楚
  • PHP/Laravel + Blade → 你們可以直接接
  • React/Vue SPA → 你們得有前端能力
  • .NET / Node → 需要先重構後端才能接前端
11
AI 影像辨識（CV）
+

不要主動承接自研 CV 模型。需要 ML 工程師、訓練資料、GPU 推論成本。

替代方案：串第三方 — Google Vision、AWS Rekognition、Azure Computer Vision。 你們收的是「整合費」與「業務邏輯費」，不是「模型費」。

12
iPad POS App 重構
+

如果現在是原生 Swift → 不要主動建議改 Flutter。 POS 對效能、藍牙、receipt printer 整合要求高，Flutter 在這些細節會踩坑。

如果現在是 Web App / PWA → Flutter 改寫可行但要小心。

策略：不主動提這題，等他們提。

Discovery Questions

這七題沒問清楚之前，不報價、不寫 SOW。

Q.01
你們現在 POS 後端是什麼語言？資料庫是 MySQL / PostgreSQL / MSSQL？
決定整合難度。如果是 PHP/Laravel，我們直接接；如果是 .NET，整合成本要重新評估。
Q.02
店家後台是 SPA 還是 SSR？前端框架是什麼？
決定我們能不能直接動既有介面。
Q.03
iPad POS App 是原生 Swift 還是 Web / Hybrid？
影響「店端改動」這條路能不能走 Flutter。
Q.04
資料量等級？多少店、多少筆交易 / 日？
決定 BI 架構（Laravel + MySQL 還是 ClickHouse）。
Q.05
有沒有現成的 API 層？還是要我們直接接 DB？
直接接 DB 是技術債陷阱，要爭取走 API。
Q.06
合作模式是包專案、駐點、還是 SI 分潤？
影響合約結構、人力配置、長期關係。
Q.07
未來維運由誰負責？我們交付後脫手，還是長期支援？
影響架構選型（要不要做高觀測性、自動化部署）。
§ 08

應避之雷

Risk Advisory

該避開或慎重的承諾 — 簽下去之前要先過自我檢查。

Six Hard Lines · 六條紅線
  • 不要承諾自研 ML 模型 — 除非你們有 ML 工程師、資料管線、GPU 預算
  • 不要承諾硬體驅動開發 — 除非你們有韌體 / 嵌入式經驗
  • 不要承諾「重寫整套 POS」 — 這是 18 個月以上的坑，是 SI 大廠才能吃下的案子
  • 不要在沒看到 SOW 之前報價 — 餐飲業客製需求很細，沒寫清楚會無限延伸
  • 不要在沒看到他們既有架構之前承諾 SLA — 老系統的耦合度是未知數
  • 不要在沒簽 NDA 之前透露我方核心技術細節 — 對方背後有鴻海，要謹慎
§ 09

術語說明

Glossary

本報告涉及的縮寫與技術名詞速查。會議時對方若提到任一詞彙，可直接對照。

商業 / 合約

SaaS
軟體即服務。雲端訂閱制軟體，按月付費而非買斷。
BI
商業智慧。把資料庫的交易紀錄轉成老闆看得懂的圖表報表。
CRM
客戶關係管理。會員資料、消費紀錄、行銷溝通的中央系統。
RFM
會員分群三維度：最近一次消費、消費頻率、消費金額。
ERP
企業資源規劃。總公司的內部後台，管財會、庫存、人資（如鼎新、SAP）。
SOW
工作說明書。合約附件，寫清楚要做什麼、不做什麼、交付什麼。
NDA
保密協議。雙方先簽，才能交換內部技術或商業資訊。
SLA
服務水準協議。承諾系統可用率（例如 99.9%）。
SI
系統整合商。專做大型整合案的公司（如鼎新顧問商）。
iPaaS
整合平台即服務。當作各系統間的「萬用轉接器」。

技術概念

API
系統與系統之間的溝通介面。POS 要傳資料給排班系統，就透過 API。
Webhook
系統主動通知對方的機制。POS 收到訂單 → 自動推一筆通知給庫存系統。
OAuth2
標準的授權登入流程。例如「用 Google 帳號登入」就是 OAuth2。
PWA
用瀏覽器開的網頁，但可加到手機桌面，操作像 App 一樣。
SPA
單頁應用。網頁不重新整理就能切換內容（如 Gmail、Notion）。
SSR
伺服器端渲染。傳統做法，每次點連結都重新讀整頁。
OLAP
線上分析處理。專為「大量資料聚合查詢」優化的資料庫類型。
LLM
大型語言模型。ChatGPT、Claude、Gemini 這類 AI。
RAG
讓 AI 回答前先去查內部資料庫，避免亂講。
CV
電腦視覺。讓電腦「看圖」辨識內容的技術。
ML
機器學習。AI 訓練模型的統稱。

餐飲場景

POS
餐廳收銀系統。負責點餐、結帳、列印發票、出單給廚房。
KDS
廚房顯示系統。把訂單顯示在廚房螢幕上，取代紙本出單。
Kiosk
自助點餐機。客人自己操作的大螢幕點餐機（麥當勞那種）。
BOM
物料清單。一杯珍奶用幾克茶葉、幾顆珍珠的成本拆解表。
ESC/POS
EPSON 制定的熱感印表機指令集。所有市售收據印表機都支援這套。
EDC
刷卡機規格。串卡機收單時要照銀行的 EDC 規範。
LINE OA
LINE 官方帳號。店家在 LINE 上的客服與行銷管道。
LINE SPOT
LINE 內建的地點服務頁面，可導流到店家。

工具 / 套件

Laravel
主流的 PHP 後端框架。本提案的後端骨幹。
Flutter
Google 的跨平台 App 框架。一份程式碼能跑 iOS / Android / Windows / Mac。
Filament
Laravel 的後台系統產生器，快速做出管理介面。
ClickHouse
專門處理大量分析查詢的資料庫，比傳統 MySQL 快幾十倍。
Redis
記憶體型快取資料庫，用於排程、佇列、即時計數。
Horizon
Laravel 的佇列管理工具。
Reverb / Pusher
即時通訊服務。讓網頁能「主動」收到伺服器新訊息（如 KDS 即時收單）。
FCM
Google 的手機推播服務。
pgvector / Pinecone
向量資料庫。AI 應用裡用來做「相似度搜尋」（RAG 的後端）。
Metabase / Superset
開源 BI 工具，可直接接資料庫產出儀表板。
